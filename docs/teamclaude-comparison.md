# TeamClaude behavioral comparison

TeamClaude is the behavioral reference for enrollment, subscription transport, account rotation, agent launchers and local services. TeamCode adds team authorization, shared SQL coordination and a native client. Similar commands do not imply behavioral parity.

This review compares TeamCode with TeamClaude commit [`88fe9b37862c40fefa459a90cd3dbd2c31db98ce`](https://github.com/KarpelesLab/teamclaude/tree/88fe9b37862c40fefa459a90cd3dbd2c31db98ce) in the sibling checkout. The review covers the paths below, not every feature or every line of either repository. Remaining findings are V1 work unless explicitly described as an intentional scope difference.

## Intentional adaptations

| Area | TeamClaude | TeamCode |
| --- | --- | --- |
| Account identity and updates | File-backed upserts, stable record IDs and atomic merges (`src/account-pairing.js`, CLI upserts) | Server-verified provider identity, SQL unique identity/version checks, encrypted credentials and preserved policy/history. No merge by array position or display name. |
| Refresh ownership | Local process/file coordination | Commit refresh intent before contacting the provider. A crashed or uncertain rotation requires reconnect instead of replaying a potentially consumed refresh token. |
| Client authentication | Direct Claude mode can preserve the user's own subscription login | Team members authenticate to TeamCode; provider credentials stay server-side. The local proxy uses a separate capability. Full Claude feature compatibility still needs real coding-task acceptance. |
| Retry policy | Includes short transient throttling waits and a bounded 5xx hop | Try eligible accounts and configured model/provider routes on definite rejection; do not automatically replay ambiguous transport failures or 5xx. No replay after client-visible output. This is conservative and may reduce availability. |
| Persistent state | Local configuration and process state | Shared SQL for accounts, refresh intent, budgets, reservations, quotas, leases and directives. In-flight HTTP/SSE parsing necessarily remains local to its request. |
| Waiting for capacity | `src/account-manager.js:admit` waits on process-local account pauses/ramp slots and checks client abandonment; `src/server.js` attaches a per-request abort signal to response close and returns 503 for its overloaded upstream admission gate | Bounded Exposed/MySQL pending metadata, member turn rotation within each pool/provider, interactive priority and background aging. Waiting consumes no reserved credit or database connection. Authorization/policy is checked atomically with reservation. Both HTTP hops enable disconnect cancellation; an authenticated SDK cancellation marker also reaches the owning server through shared MySQL when native transport disposal does not close its socket. That contract passed native Windows, macOS and Linux CI. |
| Service support | macOS launchd and Linux systemd; Windows explicitly unsupported in `src/service.js` and `test/service.test.js` | Same OS managers on macOS/Linux; native Windows Task Scheduler integration is additional TeamCode work and needs its own acceptance. |
| Windows npm commands | Node spawn with a Windows shell | Resolve supported Claude/Codex npm entrypoints to Node without a shell, preserving literal arguments and containing the process tree. Arbitrary custom command wrappers are not supported. |
| Extensibility | Provider-specific paths in the reference | Separate `ProviderTransport` implementations, inbound HTTP adapters and request/stream protocol adapters. Protocol conversion is independent of subscription hosting. See [architecture](architecture.md). |

## Remaining findings and acceptance gates

1. **Incomplete quota readings and model aliases.** TeamClaude retains observations without reset timestamps, learns named active-limit mappings, handles model bucket aliases and tolerates rounded window durations. TeamCode now persists nullable reset epochs, bounds unknown-reset exclusion to fresh observations, keeps unknown forecasts non-optimistic and tolerates rounded durations consistently across headers/usage. Codex active-limit mappings now use per-account SQL bindings; canonical `metered_feature` slugs match header families, complete probes retire model caps, and monotonic snapshot watermarks reject stale resurrection. Admission, rejection classification and forecasts share the mapping. `QuotaModelLimitsPersistenceTest` and `RouteDirectivePersistenceTest` cover independent replicas, delayed observations, provider/account isolation and retired history. Claude now uses `src/oauth.js` and `test/quota-probe.test.js`/`test/scoped-weekly.test.js` as the enumeration reference: a valid explicit `limits` array retires missing caps while valid legacy readings retain precedence. TeamCode additionally rejects malformed enumerations as removal evidence and coordinates delayed responses through SQL watermarks. `ClaudeQuotaSnapshotTest` and `ClaudeQuotaRetirementPersistenceTest` verify this behavior. More plan-specific fixtures and real quota/reset-boundary acceptance remain before claiming every quota shape is supported.
2. **Renewal failure classification.** TeamCode conservatively fences every failed refresh, including a definite transient rejection. Distinguish a definitely unconsumed token from an uncertain rotation before allowing retries. Preserve crash safety and do not copy local in-memory retry behavior into the replica deployment unchanged.
3. **Session/account affinity.** TeamClaude's session distribution, session tracker and starvation/reset tests cover warm-cache affinity and movement at quota boundaries. TeamCode now has [durable conversation affinity](session-affinity.md), independent model hints, remembered route targets, bounded persistence and two-replica tests for eligibility, expiry and revocation. Provider-managed thread IDs remain rejected. Full multi-turn real-agent acceptance and quota-expiry optimization remain open.
4. **Forecast relevance and stale measurements.** TeamClaude's `src/adaptive-distribution.js` learns over wall-clock anchors and resets its baseline across quota resets; see also `test/quota-seen-at.test.js` and `test/session-reset-race.test.js`. TeamCode now scopes advice to active targets, current model/effort policy, accessible pool accounts and weighted allowances, with durable recovery hysteresis (details below). Unknown/stale observations cannot preserve optimistic advice. Real Codex Windows acceptance, subagent fan-out and replays of outside spend, resets and bursty real-agent traffic remain required before claiming forecast accuracy or automatic orchestration.
5. **Direct login and reconnect UX.** Claude and Codex now share an OAuth enrollment client with provider-specific adapters. Both expose an authorization URL and validate a pasted result against the current state/PKCE flow; Codex uses the fixed registered localhost callback address without starting a listener. Direct Codex browser-consent acceptance remains pending. Use `src/codex-auth.js`, the login-flow modules and their callback/paste tests. Re-imported credentials must retain explicit server refresh ownership without making reconnect confusing. Test the full CLI lifecycle, not only persistence upserts.
6. **Native client feature compatibility.** Same-protocol requests preserve unrecognized fields; cross-protocol text/images/function tools and supported custom text tools are supported, while opaque reasoning, unsupported tool grammars and stored provider state fail explicitly. Real Claude Code and Codex coding tasks now pass in both directions with reasoning disabled, including Codex namespaced tools and `additional_tools` history. Both clients also complete a controlled mid-conversation fallback after native account availability is removed at a tool-result boundary. Full-default conversion reasoning and cross-provider quota/reset-boundary acceptance remain experimental; the owner moved conversion outside V1 and behind a default-off administrator setting. Native-provider quota/reset acceptance remains V1. The local API-auth mode needs validation beyond a simple Haiku prompt.
7. **Error explanations and transient availability.** Distinguish authentication refusal, entitlement cooldown, transient throttle and exhausted subscription in operator diagnostics and final client errors. Add bounded retry waiting where proven safe. A routing search limit is a 503, never a claim that all capacity is exhausted.
8. **Windows lifecycle and distribution.** Actual Task Scheduler installation/reuse/drain/restart/uninstall acceptance passed in CI `39178163269`. Clean-machine logon/reboot checks remain. System services before user login and versioned native release/update/rollback remain open. TeamClaude has no Windows service implementation to borrow.
9. **Team-only requirements.** Shared bounded queues and member turn rotation with interactive priority/background aging now have independent-pool MySQL acceptance. Native launchers support per-launch workload selection with shared-service isolation, verified on Linux/Windows CI. The shared cancellation contract also passed all three native platform jobs. Registered devices and authentication-session management now pass all three native platform jobs with shared MySQL revocation; see [device documentation](devices.md). Real-load scheduling, groups, scoped service credentials, soft borrowing, reconciliation, forecast delivery and operational restoration remain additional TeamCode requirements, not omissions discoverable by comparing with a single-user tool. Keep them visible in [V1 progress](progress.md).

The `--workload` launcher option follows the reference's `src/index.js:runCommand` delimiter rule: TeamCode flags belong before `--`, and agent arguments after it remain literal. `test/cli-env.test.js` is the reference for invocation-local proxy configuration. Workload classes are a TeamCode team-scheduling addition; they use a local inference prefix without changing the canonical upstream path, global service state or personal agent settings. The native run/service fixtures verify this adaptation.

The comparison is a working acceptance ledger. Update this file when a finding is fixed and attach runtime evidence to its pull request; do not turn an unverified behavior into a completed checkbox.

### Active-target forecast scope

TeamCode now restricts advice to recent admitted provider/model targets and validates their original protocol, current route fingerprint, model/effort policy and thinking-budget ceiling. Only accounts in the member's pool and the selectable priority tier contribute; unrelated model windows and idle providers do not promise headroom. Weighted allowance exhaustion also suppresses acceleration. Tightening/unknown data is immediate; recovery must remain stable for two minutes in shared SQL state. Domain replay tests and an actual two-connection-pool MySQL scenario cover these rules. Session claims and automatic Claude/Codex hooks are now implemented; see [agent guidance](agent-guidance.md). Real Codex Windows hook acceptance, subagent fan-out, outside-spend attribution, active-limit/family-alias coverage and real-agent load acceptance remain open.

### Native Codex guidance bridge

TeamClaude's launcher/environment behavior remains the reference for argument forwarding and provider redirection (`src/index.js:runCommand`, `test/cli-env.test.js`, `docs/accounts.md`). It has no equivalent team-scoped predictive delivery contract. TeamCode adds native stdin hooks using Codex's documented protocol, with durable server claims shared with Claude, no credential-bearing hook files, explicit hook-trust review, preservation of existing hooks and bounded silent failures. The real Codex fixture proves integration without subscription use; forecast accuracy and subagent fan-out remain separate gates.

### Unknown quota reset observations

Compared against `src/oauth.js:normalizeUsageBucket`, `src/codex-usage.js`, `src/codex-quota.js:windowBucket`, and the quota-probe/Codex usage tests. TeamCode now retains observed percentages without inventing a reset, accepts the reference's 10% window-duration tolerance and common field aliases, and preserves model scope. The team adaptation is explicit freshness in shared SQL: unknown-reset saturation expires after five minutes without new observations, while known reset dates retain their existing admission protection. Such readings never produce an acceleration forecast. Migration/independent-replica tests cover zero clearing an old saturation, late observations, scoped exclusion and freshness expiry.
