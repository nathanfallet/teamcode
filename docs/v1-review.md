# V1 review checklist

This walkthrough records product behavior and evidence. On 2026-10-20 the owner moved the remaining extended validation to V2 after boot-startup implementation and release `0.1.0`; the remaining scenarios are listed under [Owner-deferred V2 validation and operations](#owner-deferred-v2-validation-and-operations) below. Start with [current progress](progress.md) and the [TeamClaude gap ledger](teamclaude-comparison.md).

## Walk through the implemented product

1. Validate the packaged chart with bundled and external MySQL values, its schemas and documented installation steps. Deployment on an owner/user cluster is not an agent task or release prerequisite; operators can follow the chart guide on their own infrastructure. Keep the encryption key across restarts in isolated server acceptance. Confirm the image commit associated with the successful build; `latest` advances only after every required CI job passes.
2. Use the one-time bootstrap administrator password, change it, create a member in the dashboard and sign in as that member. Confirm there is no public signup and administrative pages are unavailable to the member.
3. Set the self-hosted URL with `teamcode login --server https://your-host`. Restart the CLI and check that authentication and the URL persist. Confirm password replacement and session revocation. Open **Devices**, rename the CLI installation, log out/in and confirm the same registration/name persists. Revoke one session, then an entire device, and confirm other devices/browser sessions remain usable. Verify that member usage does not reset.
4. As the administrator, inspect `teamcode accounts import --from teamclaude --dry-run`. For a temporary trial while TeamClaude remains the refresh owner, import with `--access-only`. Verify repeated import updates the same identities and preserves account settings. A permanent switch uses explicit refresh handover after the old refresher is stopped.
5. Exercise `teamcode accounts add --provider claude` and `--provider codex`. Codex's direct browser consent is the outstanding live enrollment check: paste the complete callback URL into the hidden prompt. Check reconnect/upsert and explicit ownership after enrollment.
6. Set member weights, concurrency and pool budgets in the dashboard. Configure a named shared overflow reserve without primary members, opt in one member and verify that home/source budgets and protected ordinary pools remain enforced. Grant and revoke a temporary daily allocation with a reason; inspect its normal/effective capacity, expiry and retained history, and verify no spend is refunded. Create groups with daily/concurrency caps, assign a manager and members, and check cumulative limits, scoped pause/resume and retained spend after membership changes. Set allowed models/efforts, including the decision about Fable. Confirm a rejected policy is visible to the caller and does not dispatch a provider request.
7. Run `teamcode run claude -- ...` and `teamcode run codex -- ...` with a small request. Confirm request/provider/model/account metadata and settled usage without prompts or credentials. Inspect the launch in Dashboard → Sessions and `teamcode sessions list/show`; distinguish wrapper heartbeat, native conversations and login sessions. Exercise admin run pause/lifetime/concurrency caps across replicas without resetting member/group/pool spend.
8. On a test workstation, run `teamcode service install`, then test reuse, stop/start/restart/uninstall. Actual Windows lifecycle CI and actual workstation reboot/logon evidence are separate checks; consult their latest recorded status.
9. Verify that experimental cross-provider translation is disabled in model settings by default. Configure native-provider model/account fallback and confirm the selected target. An administrator may separately enable the experimental flag and exercise the documented portable conversion profile; this optional check is not a V1 release gate.
10. Occupy physical capacity using controlled requests from multiple members. Check waiting counts, member turn rotation and background aging using `run claude/codex --workload background -- ...` or the workload header. Confirm a background launch sharing the service does not change an interactive launch's class. Cancel a pending request before any response headers and confirm its metadata disappears without reserved credits. Exercise the authenticated cancellation endpoint through another replica while the original inference connection stays open, both before headers and during streaming. Test policy/session revocation while pending. Upgrade all replicas and the local CLI before expecting this behavior end to end.

11. Open **Audit** as an interactive administrator. Inspect bootstrap/member/account/policy/credential events, follow the older-page cursor and verify API access through `GET /api/v1/audit`. Ordinary members and service/CI keys must be denied. No passwords, tokens, prompts or response bodies should appear.

## Experimental conversion follow-up (not a V1 release gate)

The owner explicitly deferred Claude/Codex conversion on 2026-10-19. It is disabled by default and requires the administrator model-setting flag. Keep native-provider client/tool/quota acceptance in V1.

- **Cross-provider portability:** complete coding tasks are verified in both directions with reasoning disabled: Claude built-in Read/Edit/Bash and Codex namespaced/code-mode tools, including `additional_tools` and replayed custom tool calls. Finish full-default-client and reasoning acceptance; the [default-reasoning probes and exact request blockers](reasoning-portability.md) now reproduce both directions. Both clients also complete a task after the native provider is disabled at a tool-result boundary, using the unchanged fallback route. These controlled portable-profile tasks do not prove every route or an actual quota/reset boundary. Opaque signed/encrypted reasoning, hosted tools and unsupported custom grammars remain explicit limitations. Native passthrough retains their original fields; crossing protocols does not currently preserve every such feature.
