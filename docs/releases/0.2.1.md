# TeamCode 0.2.1

A small release: `teamcode` works by name right after installation, and interactive Claude Code logged in with a claude.ai subscription works through `teamcode run claude`.

## Highlights

- **Command on PATH.** `teamcode install` (and the install scripts) now make `teamcode` available by name, without administrator rights. On macOS and Linux it creates a symbolic link `~/.local/bin/teamcode` to the stable launcher, so updates and rollback need no relinking, and prints the exact `export PATH=...` line when `~/.local/bin` is not in your PATH. On Windows it appends the launcher directory to your user PATH (open a new terminal). A file or link that TeamCode did not create is never replaced; the installer explains and exits with an error. Re-running the installer changes nothing. `teamcode install --no-path` skips this step. See [Command on PATH](https://github.com/nathanfallet/teamcode/blob/0.2.1/docs/bootstrap.md#command-on-path).
- **Fix.** The local proxy token is passed to Claude Code as `ANTHROPIC_AUTH_TOKEN`, so it takes precedence over a claude.ai subscription login without a prompt and the proxy no longer answers 401 (#28).

## Upgrade

```sh
curl -fsSL https://github.com/nathanfallet/teamcode/releases/download/0.2.1/install.sh | sh
```

```powershell
$f = Join-Path $env:TEMP 'teamcode-install.ps1'; Invoke-WebRequest -UseBasicParsing 'https://github.com/nathanfallet/teamcode/releases/download/0.2.1/install.ps1' -OutFile $f; & ([scriptblock]::Create([IO.File]::ReadAllText($f))); Remove-Item $f
```

Existing installations can run `teamcode update`; run `teamcode install` once afterwards (or use the install script) to get the command link or PATH entry. The server is unchanged; pin `image.tag: "0.2.1"` to keep versions aligned.

## Scope and follow-up

The command-link logic is covered by unit tests with real symbolic links (JVM and native macOS) and by the extended installation and bootstrap smokes, which run on the signed bundles of the full validation.
