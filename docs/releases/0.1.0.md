# TeamCode 0.1.0

Initial release of the standalone, self-hosted team proxy for pooled Claude Max and Codex subscriptions.

- Ktor server, native Kotlin Multiplatform CLI, typed API/client and web administration dashboard.
- Administrator-created team accounts, devices, scoped service keys, weighted daily allowances, model/effort policies, protected pools and explicitly shared overflow capacity.
- Claude/Codex enrollment and TeamClaude import/upsert, encrypted provider credentials, coordinated refresh, native streaming, bounded account/model failover and shared usage accounting.
- Group and agent-run limits, audited temporary allocations, unknown-usage reconciliation, predictive pacing and local agent guidance.
- Native launchers, login/boot startup, signed installation/update/rollback and an opt-in automatic updater.

## Install

macOS ARM64/Intel and glibc Linux ARM64/x64:

```sh
curl -fsSL https://github.com/nathanfallet/teamcode/releases/download/0.1.0/install.sh | sh
```

Windows x64, using Windows PowerShell 5.1 or PowerShell 7:

```powershell
$f = Join-Path $env:TEMP 'teamcode-install.ps1'; Invoke-WebRequest -UseBasicParsing 'https://github.com/nathanfallet/teamcode/releases/download/0.1.0/install.ps1' -OutFile $f; & ([scriptblock]::Create([IO.File]::ReadAllText($f))); Remove-Item $f
```

Use the printed launcher path or add its `bin` directory to PATH, then:

```sh
teamcode login --server https://your-teamcode.example.org
teamcode run claude -- --dangerously-skip-permissions
teamcode run codex -- exec "Explain this repository"
teamcode service install
```

`service install --at-boot` (alias `--system`) opts into startup before login. macOS requests administrator authorization for a LaunchDaemon running as your user; Linux enables user-manager lingering; Windows requires an elevated terminal and a masked Windows-account password prompt for a least-privilege boot task. Credentials must be available to that user at boot. See the [service guide](https://github.com/nathanfallet/teamcode/blob/0.1.0/docs/services.md).

Linux needs the shared libraries documented in the [installation guide](https://github.com/nathanfallet/teamcode/blob/0.1.0/docs/bootstrap.md), including libcurl and OpenSSL libcrypto. Windows ARM64/32-bit targets are not included.

## Deploy your server

Image: `nathanfallet/teamcode:0.1.0`. The chart defaults to the tested main image's `latest` tag; set `image.tag: "0.1.0"` to pin this release.

```sh
helm upgrade --install teamcode \
  https://github.com/nathanfallet/teamcode/releases/download/0.1.0/teamcode-0.1.0.tgz \
  --namespace teamcode --create-namespace -f values.yaml --wait --timeout 10m
```

Supply your own secrets, public URL, ingress and database values as described in the [chart guide](https://github.com/nathanfallet/teamcode/blob/0.1.0/helm/teamcode/README.md). Users deploy on their own infrastructure.

## Scope and follow-up

Cross-provider conversion is experimental and disabled by default. Open-source providers, cloud sessions, centralized MCP and skills remain V2. Under the owner's finalized release scope, additional real-client/quota-boundary/load/workstation and operational validation is tracked in the [unfinished V1 handoff](https://github.com/nathanfallet/teamcode/blob/0.1.0/docs/v2-validation-handoff.md). It covers V1 carry-over only, separately from new V2 features. The [testing playbook](https://github.com/nathanfallet/teamcode/blob/0.1.0/docs/testing.md) documents reproducible native, real-client and real-subscription checks. Publication does not claim those deferred scenarios passed; the release workflow gates publication on its built-in native, signed-installation, JVM/replica, Helm and image checks.
