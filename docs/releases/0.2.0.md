# TeamCode 0.2.0

Adds the first V2 features on top of 0.1.0: cloud sessions on Kubernetes, a team MCP gateway, a server-side skill catalog and per-member environment and MCP variants. It also fixes the dashboard login behind browsers that strip the `Origin` header.

## Highlights

- **Cloud sessions.** Members start coding sessions that run on the operator's Kubernetes cluster: leased reconciler, environment preparation, transcript and messages, `attach`, idle pause with attachment leases, an `initialMessage` on creation, transfer between members at a paused boundary, and deletion that is proven before it is reported. The agent runs in its own container under its own UID and reaches inference through a loopback proxy with short-lived `tcex_` credentials. Members' GitHub accounts link to the team's GitHub App; the credential helper renews the owner's token. Cloud scopes `cloud:read`, `cloud:write` and `admin:cloud` exist for service keys. Cloud sessions are off until an administrator configures a cluster.
- **MCP gateway.** One endpoint per MCP server, connected automatically by `teamcode run`, also available inside cloud sessions.
- **Skills.** A server-side skill catalog with CI publication and delivery to members, also available inside cloud sessions.
- **Variants.** Environment and MCP variants with per-member assignments; cloud sessions receive the owner's environment variables.
- **Fix.** Dashboard forms work again when the browser sends no `Origin` header (same-origin referrer policy) (#17).
- **Build.** The server image is built with the Ktor Gradle plugin (Jib) instead of a Dockerfile.

## Upgrade

Install and deploy as for 0.1.0, replacing the version:

```sh
curl -fsSL https://github.com/nathanfallet/teamcode/releases/download/0.2.0/install.sh | sh
```

```powershell
$f = Join-Path $env:TEMP 'teamcode-install.ps1'; Invoke-WebRequest -UseBasicParsing 'https://github.com/nathanfallet/teamcode/releases/download/0.2.0/install.ps1' -OutFile $f; & ([scriptblock]::Create([IO.File]::ReadAllText($f))); Remove-Item $f
```

Existing installations can run `teamcode update`. For the server, pin `image.tag: "0.2.0"` (image `nathanfallet/teamcode:0.2.0`) and follow the rolling upgrade procedure in the [operations guide](https://github.com/nathanfallet/teamcode/blob/0.2.0/docs/operations.md). Database migrations apply on start and are ordered after the 0.1.0 history. Take a recovery checkpoint first.

```sh
helm upgrade --install teamcode \
  https://github.com/nathanfallet/teamcode/releases/download/0.2.0/teamcode-0.2.0.tgz \
  --namespace teamcode --create-namespace -f values.yaml --wait --timeout 10m
```

## Scope and follow-up

Cloud sessions are covered by unit and integration tests with a fake cluster. The opt-in `scripts/smoke-cloud-kind.py` real-cluster smoke was replayed on a local `kind` v0.33.0 cluster after fixing two defects in the smoke itself (the stand-in runner image did not create `/usr/local/bin`, and the test expected the bootstrap member to be an administrator instead of the owner); it now passes end to end: workspace claim, pod, TokenReview, pause with checkpoint and proven deletion of the claim and PersistentVolume. Real provider credentials and Claude Code inside a cloud session are not part of this release's acceptance. Cross-provider conversion stays experimental and disabled by default. The scenarios still open from 0.1.0 remain listed in the [validation handoff](https://github.com/nathanfallet/teamcode/blob/0.2.0/docs/v2-validation-handoff.md).
